# UCIE 소유자 로컬 — 짧은 질문 입력과 공식 근거 1차 답변 (2026-11-15)

## 정확한 개발 범위

사용자 목표: 고객이 자신이 겪는 코딩 문제를 직접 설명하면 UCIE가 가능한 원인·확인 절차·공개 근거·해결 방향을 알려주는 제품. 기존 기술 가이드·SkillBook·4대 엔진은 그 답변을 뒷받침하는 기반이다.

이 PR은 **소유자 Windows localhost의 실제 질문 입력 UI와 인메모리 분석/근거 출력 경로**를 개발한다. 그러나 외부 AI 모델이 연결되지 않았으므로 **생성형 AI가 자유 질문을 이해하는 시스템은 아직 아니다**. 현재는 네 개의 기검증 고정 기술 사례에 문구가 명확히 일치하는 경우에만 기존 UCIE 공식 출처 기반 안내를 제공한다. 그 외 질문은 임의로 해결책을 지어내지 않는다.

## 사용자 동선

기존 실행: D:\UCIE\scripts\start_ucie_local_v1.ps1

홈의 '내 문제 직접 설명하기' → GET /local/ask → 일반적인 증상을 12~360자로 입력 → POST /local/ask → 정확히 한 가지 알려진 증상으로 분류 → 가능한 원인·두 가지 점검 방법·안전한 다음 행동·공식 문서 링크·UCIE 공개 도서관 링크.

현재 대표 유형: Python 패키지/모듈 찾지 못함, PowerShell 명령 찾지 못함, Git 저장소 아님, MCP prompts/get 인수 오류. 기존 GET /local/solve 및 4대 기능/SkillBook은 그대로 이용 가능.

## 입력·전송 경계

- 소스코드·원본 로그·비공개 경로·URL·이메일·전화번호·토큰·암호·개인정보를 입력하지 말라는 경고를 표시한다. 의심 패턴은 422로 거부하고 입력 원문은 절대 화면에 반사하지 않는다. 이 정규식 필터가 모든 비밀이나 개인정보를 완벽하게 감지하는 것은 아니며 **상용 고객 입력 허용 승인이 아니다**.
- 질문은 URL이 아니라 브라우저의 POST 본문 한 필드로만 전달한다. 127.0.0.1 정확 Host/Origin, 하나의 Content-Length, 엄격한 application/x-www-form-urlencoded 타입, 길이 제한을 검사한다. 중복 필드, 잘못된 UTF-8, 대용량, 크로스 오리진, 다른 경로 POST 차단.
- 입력은 해당 HTTP 요청 메모리 안에서만 분석하며 응답에 반복하지 않고, 디스크/SQLite/로그/GitHub/Slack/외부 모델/검색 서비스에 저장·전송하지 않는다. 외부 코드 실행, 임의 셸 실행, 파일/비공개 저장소/타 프로젝트 접근, 운영 데이터베이스 수정, 자동 규칙 승격, 결제, 고객 배포 없음.
- 답변은 기존 UCIE 로컬 카탈로그에서 검토한 정적인 공식 문서 링크를 재사용한다. **실제 원인을 독립 검증한 것, 문서를 실시간으로 읽은 것, 개인 코드를 고친 것이 아님**.

## 진정한 AI 문제 분석의 남은 P0 범위

GitHub Issue #275: 더 일반적인 질문/코드/로그 처리의 별도 범위·동의/보존/삭제 정책, 실제 모델 제공자 또는 온디바이스 모델 연결, 공식 출처·버전·오류 확신도 구분, 재질문·수정 후 회귀 절차, 프롬프트 인젝션과 비밀정보 누출 대응, 실제 Windows 브라우저 사람이 판단하는 품질 시험. 이러한 승인 없이 UCIE 고객 데이터 수집 범위를 확대하지 않는다.

정기결제·상용 서명·고객 배포는 소유자의 명시적 결정에 따라 계속 보류한다. 신규 테스트 통과만으로 LLM 통합/상용 허용/실제 사용성 수락을 선언하지 않는다.
