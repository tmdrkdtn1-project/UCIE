## 1. 경영 판단 요약

**결론: 개발을 지속할 기술적·상업적 가설은 있으나, 현시점 UCIE를 '확실히 차별화된 유료 제품'으로 판단할 수 없다.**

1. **인접 유료 시장 및 검증 필요성은 확인됨:** 코드 리뷰·정적 분석·AI 스킬/에이전트 시장이 존재하고, 개발자 설문에서는 검증 가능성이 중요하게 나타남.
2. **UCIE 직접 유료 수요는 미검증:** 실제 UCIE 고객의 지불 의향, 전환율, 유지율, 구매 결정자, 채널, 원가, 비교 우위 데이터 없음.
3. **기술적 포지션:** 출처·버전·권리·독립 시험을 연결해 **재가공 가능한 스킬서적/실행형 기술 자산**을 생산하는 것에 잠재력. 단순 수집·분류·요약·스킬 폴더 제작은 차별화 요인이 아님.
4. **권고:** 코어 도서관은 보존·발전하되, 제한된 기술 분야에서 **검증된 한 권의 스킬서적 + 안전한 재사용 모듈**을 실제로 만들고 무료 대안 대비 효과 및 첫 고객 유료 의사를 측정한 후 상용화 결정.

## 2. 제품 정의를 축소하지 말 것

UCIE의 최종 목표는 네 동등한 축으로 구성됨:

1. 코딩 오류 예방 지식(안전한 호출·버전 적합성·재현·회귀시험).
2. 오류 외의 가치 있는 개발/유지보수 엔진·스킬·알고리즘·학습 로직의 발견·일반화·개선.
3. **가상도서관과 스킬서적 생산**: 검증된 기술 지식을 원리 수준으로 재가공하고 문제·업무 중심으로 재분류한 뒤 사람이 읽는 기술서적 및 AI/프로그램이 사용하는 재사용 패키지로 구체화.
4. UCIE 자체 허용 실험·개정 경험을 이용한 지식 품질과 재사용 능력의 지속 개선.

필수 가치사슬: **승인된 공개 근거 수집 → 중복 제거·원리 추출·일반화 → 기술별 재분류·챕터 구성 → 사람/기계 소비 형태 생산 → 안전한 시험·독립 검증 → 사용권·보안·사람 승인 → 버전 고정 배포 → UCIE 자체 경험으로 개정**.

스킬서적은 단순 PR 목록, 데이터베이스, AI가 생성한 설명문, 증거 없는 에이전트 프롬프트가 아니다. 실제로 사람이 이해하고 소프트웨어가 재사용할 수 있는 **버전·전제조건·금지 조건·출처·시험 결과가 추적되는 기술 자산**이어야 한다.

이 외부 자료들은 **사업 환경 비교를 위한 공개 근거**일 뿐, UCIE 공개 마이너의 신규 수집 출처·허용 URL·학습 입력으로 자동 승격시키지 않는다. 실제 마이너는 기존 승인된 공식 기술 자료와 다섯 공개 저장소 범위만 유지한다.

## 5. 권장 고객·패키지·수익화 가설

현재 승인된 공개 기술 범위 안에서 먼저 시험할 고객: **Python·PowerShell·Windows 자동화 유지보수 및 개발팀**, 다음으로 AI 코딩 에이전트 개발팀.

- **무료 탐색:** 공개 메타데이터 검색, 출처 확인, 미검증 상태가 분명한 읽기 전용 정보.
- **유료 후보 A — 검증된 기술 스킬서적:** 문제 중심 기술 챕터, 지원 버전·전제조건·반례·테스트 레시피·개정 알림.
- **유료 후보 B — 머신 소비 패키지/API:** 독립 소비자가 확인하는 검증된 실행 계약·버전·안전한 입력/출력·변경 이력.
- **유료 후보 C — 조직용 검증·변경 영향 보고:** 감사 가능한 근거 및 기술 최신성 관리.

**가격 미결정:** 이전 대화의 가격대·30팀 매출 사례는 검증된 수요 데이터가 아닌 예시였으므로 이 문서의 사업 전망이나 승인 가격으로 사용하지 않는다. 무료 경쟁 제품과 실제 고객 비용을 비교한 뒤 가격 시험을 진행한다.

## 6. 구현 증거와 불확실성

- 기존 개발 정본과 [2026-10-28 P9 통합 명세](UCIE_P9_PRODUCT_INTEGRATION_20261028.md)에는 검색·분류·UCIE 자체 합성 실험·제한된 독립 소비/규칙 검증 기능이 기술돼 있다. 이들은 **완성된 범용 스킬서적 생성 엔진**의 증거가 아니다.
- [2026-11-02 SkillBook 제품 계약](UCIE_SKILLBOOK_PRODUCT_MISSION_V1_20261102.md)과 [PR #172](https://github.com/tmdrkdtn1-project/UCIE/pull/172)는 목표를 고정하고 **metadata-only blueprint** 초안·실패 조건을 코딩하는 변경. 일반화된 챕터 실제 집필, 크로스소스 의미적 합성, 독립 시험을 통한 스킬 효용, 권리 검증, 외부 상품 출시 **미완**.
- 합성 테스트 PASS는 UCIE 자체 로직의 제한된 결과이며 외부 기술의 실제 성능·법적 재배포 권한·상용 품질을 인증하지 않는다.
- GitHub CI, 운영자 Windows 호스트 관측, 규칙 서명·승인, 외부 유료 고객 확보는 각각 **서로 다른 검증 단계**. 증거가 없으면 PASS로 표기하지 않는다.

## 7. 제품-시장 적합성 실험 및 중단/진행 판정

**단계 1 — 제품 실험**: 기존 허용 출처의 소규모 사례를 이용해 **실제 검증 가능한 스킬서적 1권**(최소 완결형 기술 챕터 여러 개)과 그에 결합한 **안전한, UCIE 자체 작성 재사용 기술 모듈 1개**를 만든다. 후보 메타데이터만 생성한 것으로 성공 처리하지 않는다.

**단계 2 — 비교시험**: 동등한 개발 과제를 무료 검색/기본 AI 에이전트 스킬/UCIE 스킬서적으로 수행해 결과 정확성, 미탐·오탐, 재현성, 적용 버전, 소요 시간, 운영 유지비를 기록한다. 실패 사례도 공개 가능한 근거 범위 안에서 기록한다. 타 프로젝트 비공개 자료는 UCIE 전역 지식으로 수집하지 않는다.

**단계 3 — 시장검증**: 초기 제안 표본은 잠재 구매팀 15~20곳 인터뷰, **3곳 이상의 실제 유료 파일럿** 성사 여부와 반복 사용 의사 확인. 이는 **실험 목표값**이지 실현된 고객·매출이 아니다.

**진행 조건:** 현행 무료 대안 대비 반복적으로 측정 가능한 개선, 검증 비용을 포함한 수익성 가설, 고객의 실제 지불 행동, 라이선스/보안/버전 범위 확인이 함께 필요.

**중단/전환 조건:** 차별화 성능이 재현되지 않음, 유료 고객 0 또는 유지율 부진, 검증·버전 유지비가 고객 편익을 지속 초과, 출처 사용권/재배포 권한 불확실. 이 경우 스킬서적 단독 유료 판매를 보류하고 검증 API 등 좁은 모델로 전환 검토.

## 8. 최종 기록 / 역할 구분

- **사업방 판정:** 시장 존재 = YES; 일반 스킬 생성의 독창성 = NO; UCIE 직접 유료 수요 = NOT_VERIFIED; 확실한 차별화 = NOT_VERIFIED; 본격 유료 출시 = NO_GO; 제한된 비교실험·구매 검증 = RECOMMENDED.
- **개발방 인계:** 스킬서적 실물 생산·독립시험·버전/권리 관리·재사용 계약의 종단간 실험을 우선하고, 새로운 수집 후보 수 증가만을 성과로 보지 말 것.
- **운영 제약:** 신규 마이너 수집원/스케줄러/운영 DB/서명·승인·배포 자동화 변경 없음. 다른 프로젝트나 비공개 자료 접근 금지. 이 문서를 사업 근거로 사용하되 글로벌 학습 소스로 입력하지 않음.
- **문서 승인 상태:** 리뷰 기록 / 가격·출시·상용 수요 실증 **미승인**. 기술 개발 PR 병합과 별개.

## 9. 고객 의뢰가 지식 자산을 증식시키는 경우의 비용·권리 위험 — 2026-11-02 보완

### 고객의 문제제기와 실제 사업 모델

원래 우려는 **공용 스킬서적의 저장 용량이 사용자별로 복제되는 문제**가 아니라, **이용 고객이 의뢰한 새로운 코딩 작업·스킬·기술 개선이 계속 신규 기술 후보를 만들고, 이를 UCIE 공용 지식 자산으로 재가공하고 검증할수록 과거 자산의 지속 관리 비용까지 누적되는 구조**이다. 기존 '사용자 수 증가 = 검색/API 비용 증가' 설명은 핵심을 충분히 다루지 못했다.

**사업적 플라이휠 가설:** 신규 고객/의뢰 증가 → 새 기술 문제·방법 후보 증가 → 적격 근거 추출·정리·비교·시험 → 고유 스킬/스킬서적 증가 → 기술 라이브러리 효용 증가 → 재사용·구매 고객 증가. 단, **고객 의뢰의 모든 코드·자료가 당연히 UCIE의 소유 또는 공용 학습 자산이 되는 것은 아니다.** 검증·권리·보안·수집원 승인 조건을 충족하지 못하면 후보 자체를 공용 라이브러리로 반출할 수 없다.

### 원가가 누적되는 방식

- 신규 의뢰 처리량은 고객당 평균 의뢰량이 고정일 때 대체로 고객 수에 비례한다(자동으로 지수 증가한다고 단정하지 않음).
- 운영비에는 **새 의뢰 처리비 + 신규 고유 자산 검증비 + 이미 축적된 모든 유효 자산의 유지·호환성·재검증비 + 관련 스킬 개정/폐기비**가 동시에 포함된다.
- 어떤 스킬의 의존성·런타임·규칙이 변할 때 연계 스킬을 일괄 재검증하는 구현은 스킬 수 × 지원 버전 × 실행 환경 × 변경 영향 범위에 따라 비용이 급증할 수 있다. 모든 자료/스킬 쌍을 비교하는 방식의 부적절한 구현은 제곱에 가까운 분석 비용을 유발할 수 있다.
- **결정적인 경영 지표는 월 저장량이 아니라 ‘새로 승인된 독립 재사용 자산당 총원가’와 ‘활성 스킬 자산 전체의 월간 유지·재검증 부채’**다.

### 기여 자산의 소유권과 UCIE 현재 허용 범위를 혼동하지 말 것

**현행 UCIE는 공개자료 전용이고 고객의 비공개 코드, 프로젝트, 업무 의뢰, 대화, 연결 앱, 파일, 내부 로그를 수집해 공용 도서관에 학습시키는 것을 금지한다.** 고객이 서비스를 사용했다는 사실, 유료 계약, 익명화 주장만으로 소유권·기여 동의·공용 재사용 허가가 생기지 않는다. 따라서 현행 구조에서는 고객 증가가 **자동적으로 UCIE의 공용 기술 데이터 증가를 뜻하지 않는다**.

향후 고객 기여를 사업 모델로 검토하려면 **별도 사업·보안·권리 설계와 소유자의 명시적 범위 변경 승인**이 선행되어야 한다. 그 전에는 고객 고유 요청은 공용 지식 자산이 아니라 **분리 보호해야 하는 고객 자료**로만 취급한다. 향후 공개 기여 가능 경로도 권리자가 명확한 공개 기술 자료, 재사용 라이선스, 출처 식별, 명시적 기여 권한, 옵트아웃/철회, 범위 승인 등을 별도로 충족해야 한다. 현행 승인된 공식 자료와 5개 공개 저장소 외 입력은 **자동 수집·승격 금지**이다.

### 비용 제어 설계 가설(개발 허가 아님)

1. **전수 수집과 전수 재가공을 분리**: 모든 고객 의뢰를 영구 자산으로 만들지 않는다. 현행 범위 내에서 승인된 공개 근거만 임시 후보화하며 중복·신규성·검증 가능성·반복 수요로 선별.
2. **원본 전체 재분석 금지**: 기존 근거 SHA·버전·주제·의존성 키로 동일 내용을 재사용. 새 근거로 바뀐 항목과 연관된 스킬만 증분 처리.
3. **비용 예산과 품질 게이트**: 입고 후보 상한, 분석 토큰/CPU 한도, 독립 시험 예산, 보류/폐기/정책상 배제 결정, 무한 재시도 금지.
4. **스킬별 생애주기 책임 산정**: 생성 시점 외에도 호환성 변경·정기 업데이트·보안 재시험·폐기·사용권 철회 비용을 추적.
5. **가격 구조 검증**: 공용 검증 자산의 탐색/재사용과 고가의 신규 검증·스킬 제작 의뢰를 다른 과금 단위로 분석. 무제한 신규 스킬·자동검증을 저가 정액제로 제공한다고 가정하지 않음.

### 상용화 판정에 추가할 지표

| 지표 | 정의·주의 |
| --- | --- |
| 적격 기여율 | 전체 의뢰가 아닌, **권리·출처 범위가 승인된 독립 공개 후보** / 제안된 후보. 0일 수 있음 |
| 실질 신규성 비율 | 승인 후보 중 기존 지식과 중복되지 않는 고유 기술 수 / 적격 후보 수 |
| 스킬 자산당 총생애주기 원가 | 추출+검증+구성+버전 개정+유지·폐기 비용 / 적격·실제 재사용 가능한 스킬 수 |
| 활성 스킬 자산 월 유지비 | 호환성/변경 감시/재시험/출처 정정/폐기 처리 비용(해당 기간) |
| 자산 재사용률 | 분석 기간 동안 동일한 검증 기술이 독립된 허용된 작업에 재사용된 횟수. 사용자 프로젝트 데이터는 공용 원장에 유입 금지 |
| 유료 매출 대비 지식 유지비 | 검증된 관련 매출과 기여 자산 유지비를 동일 기간·범위로 비교. 아직 실측 없음 |

**추가 사업 판정:** 적격·권리 승인된 고객 기여가 축적될 수 있다면 장기 차별화와 고객 네트워크 효과의 가능성이 있으나, **현행 UCIE에는 고객 기여 학습 기능이 없고 소유권/동의/수집원 경계가 우선**이다. 따라서 고객 수 증가에 따라 자체 지식 자산이 자동 증가한다는 수익 모델이나 예산을 **현재 확정 제품 능력으로 사용하지 말 것**. 기술·법적 허가 후 유입 대비 지속 유지비를 측정하기 전 유료 무제한 스킬 제작을 약속하지 않는다.
