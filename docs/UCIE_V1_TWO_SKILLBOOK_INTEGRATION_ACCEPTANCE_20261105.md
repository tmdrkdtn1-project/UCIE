## 1. 요청한 5개 작업을 한 묶음으로 처리한 근거

| 작업 | 실제 결과 및 한계 |
| --- | --- |
| ① 실제 Git 호환성 | 소유자 PC Git 2.55.0에서 새 UCIE 임시 저장소를 만들고 `git init/add/commit/status --porcelain=v1 -z` 출력 4개(수정1, rename1, 미추적1, ignored1)를 실제 파서가 정확히 집계. 이름은 결과에서 삭제 |
| ② 두 SkillBook 사용 흐름 | 새 `tests/test_ucie_skillbook_002_real_git_v1_integration.py`가 공통 도서관/HTML/원본 SHA/JSON 계약과 001 scandir, 002 실제 Git 바이트를 함께 검증. 전체 두 책 코드는 PR #181에만 존재하므로 정확한 PR HEAD CI가 인수 증거 |
| ③ 중복·의존성 정리 | 기존 W01 공급원, W02 `build_library_entry`, 공통 `/catalog`·`/skillbooks`, 미승인 출시 게이트 재사용. 새 수집기·검색 엔진·승인 플랫폼 **없음** |
| ④ PR 통합 준비 | 부모 PR #177 HEAD `191e2d45ddfdf8142c1979c95e1acb97ad85c11e` (Draft, 미병합). 자식 PR #181은 정확한 HEAD 기반. 비교 결과 자식 ahead, behind=0, merge-base=부모 HEAD |
| ⑤ V1 보고 | 본 인수 보고와 CI 기록. 제품의 일부 기능은 검증됐으나 전체 P9 인수·외부 배포는 **NO_GO** |

실제 Git 시험은 **전용 테스트 파일 안에서만** Git 바이너리를
호출한다. 운영용 SkillBook 레시피는 이미 전달받은 bytes를 해석할
뿐 Git 명령을 실행하지 않는다. 테스트가 새로 만드는 임시 저장소
바깥으로 접근하는 것을 막기 위해 상속된 `GIT_*` 환경설정을 제거하고
시스템/전역 설정, hook, template, signing, 네트워크 프로토콜을 차단,
`shell=False` 및 고정된 Git 동작만 허용한다. 모두 임시 저장소 내부
변경이다. Git 실행 실패는 PASS/SKIP가 아니라 **실패**이다.

## 2. 공식 출처와 구현을 혼동하지 않는다

- SkillBook 001: 공식 `python/cpython` v3.15.0 `Doc/library/os.rst`,
  SHA-256 `9d78f43c4d521c1adfe339731628feadc834728ff09112c29e63ebc09406c45a`.
- SkillBook 002: 공식 `git/git` v2.51.0
  `Documentation/git-status.adoc`, SHA-256
  `1cdd1c7339dfc64093687b6e072d59feee584b8639c0203ece0a1150ce23d325`.
- 소유자 PC 테스트 바이너리 Git **2.55.0**은 공식 문서 고정 태그
  v2.51.0과 **서로 다른 식별자**. 전 버전 호환성의 보증이 아니다.
- Git 임시 저장소의 실제 `-z` rename 기록에는
  NUL 구분 대상/원본 경로가 있었고 파서에서는 두 필드가 한 엔트리로
  집계됐다. 실제 항목 수 4개에 `max_entries=3`을 적용하면 실패한다.
- Python 001은 별도의 임시 파일 두 개를 이름 순서대로 반환한다.
  두 원본 출처 SHA, 기술 계약, 재현 입력은 섞지 않는다.

## 4. 병합 순서와 소유자 로컬 보호

1. 부모 Draft PR #177이 현재 main과 병합 가능한지 별도 검토한다.
   최종 병합 전 실제 충돌 여부와 변경 파일 범위를 재확인한다.
2. 부모를 별도 승인한 다음 자식 Draft PR #181을 **부모에 의존한
   변경으로** 검수한다. HEAD가 바뀌면 그 SHA에 대한 CI를 다시 본다.
3. 소유자 `D:\UCIE`에는 운영 `worker.py`와 수집 스크립트 등
   **기존 추적 수정 파일이 15개** 있고, SkillBook 제품 코드는 PR과
   아직 동일하지 않다. 이들 파일을 reset, overwrite, checkout,
   stage 또는 merge했다고 주장하지 않는다.
4. 현재 소유자 PC의 실제 Git 출력/파서 테스트는 성공했지만,
   **두 책 통합 테스트는 로컬 코드가 아직 001만 지원해 실패**했다.
   해당 기능 인수는 완전한 PR #181 체크아웃의 CI에서만 판정한다.
   거짓 로컬 PASS나 임의 SKIP로 이 차이를 감추지 않는다.
5. 로컬 채택이 승인된다면 충돌 파일의 원본 SHA와 백업을 확보한 후
   정확한 파일만 이식하고 다시 테스트한다. 자동 병합·릴리스 금지.

`PYTHONPATH=src`로 환경을 설정한 후:

```text

python -B -m unittest discover -s tests -p test_ucie_skillbook_002_git_porcelain_v01.py -v
```

파일을 대상으로 하는 검증, 모든 Git 버전 보증이나 독립 QA가 아니다.
