# UCIE P8 — 경험 기반 지식 진화 폐회로 V1 (2026-10-27)

## 목표와 현재 증거

UCIE 최종 4대 목표 중 **4번: UCIE 자체 실험·성공·실패·기술 검증 경험을 다음 엔진·스킬 개선에 재사용**을 실제 작동하는 작은 시스템으로 시작한다.

기준 W08 소유자 실호스트 제공 결과: 1,536 합성 항목 / 48개 조회(히트 42, 미스 6) / 3회 측정; 완전 일치 48/48, 불일치 0, 선형 비교 73,728회 vs 인덱스 생성+조회 1,584회, 중앙값 6,409,500ns vs 218,100ns, 합성 SHA256 `cd68799042a9c6c57b15100947541f16731d4cfd18efe6088db85264e92227f7`. **관측 출처는 사용자 제공이며 제3자가 독립 재현·서명한 측정이 아님**. 실제 운영 검색 인덱스 적용이나 다른 프로젝트 코드/모델의 효용 증명이 아니다.

## 진화 알고리즘

<유한한 UCIE 자체 실험의 학습 루프>

1. **OBSERVE / 경험 인수:** 기존 W08의 정형화된 실험 결과에서 알고리즘, 합성 데이터 SHA, 정확 일치 여부, 작업량·시간만 수용. W08 현행 내부 모듈을 *직접 다시 실행*하여 새 결과 생성. 임의 사용자 JSON·비공개 코드·외부 패치·PR 원문을 자동으로 경험 원장에 넣지 않음.
2. **VALIDATE / 근거 경계:** W08 최종 스키마, 정확 일치, 합성 자료 생성 SHA, 작업량 공식(기준선 N×Q, 인덱스 생성+검색 N+Q), 안전 플래그, 한계 값을 검증. 수행 시간은 호스트별 편차가 있으므로 생산 성능 보장이 아님.
3. **COMPARE / 비교:** 정확 일치가 깨지거나 작업량 이득이 없으면 `REJECT_OR_REVISE_SYNTHETIC_CANDIDATE`. 일치+작업량 이득일 때도 `SYNTHETIC_CANDIDATE_WORTH_MORE_TESTING`까지만 인정.
4. **HYPOTHESIZE / 다음 개선 가설:** `HASH_INDEX_REDUCES_EXACT_QUERY_OPERATIONS_BUT_NEEDS_DIVERSE_WORKLOADS`처럼 검증 가능한 질문으로 변환. 단순 PASS 복제·AI 모델 가중치 학습이 아님.
5. **PLAN / 중복 없는 차기 실험:** UCIE 도서관의 작고(256×16), 크고(4096×16), 조회 밀도가 높고(1536×96), 가장 큰(4096×96) 4종 안전 합성 부하를 **순서대로 한 번씩** 선택. 이미 원장에 있는 동일 부하를 다시 실행하지 않음. 부정 결과면 다음 단계 HOLD, 수동 원인 확인 필요.
6. **EXECUTE / 실제 코드 실기:** 다음 선택 항목을 실제 `evaluate_synthetic_library_index`에서 3회 실행. 비교·실측·오류/미스 0 판단. 코드의 정확한 원본과 테스트를 유지.
7. **REMEMBER / 경험 기록:** 기본 실행은 영속 기록 없이 안전한 프리뷰. 소유자가 명시적으로 `--record`하면 **UCIE 전용** `D:\UCIE\runtime\ucie_p8_experience_v1.jsonl` 파일에 *최소한의 정형 결과만* 기록. 순번·이전 SHA256·정규화된 현재 결과 해시로 순서를 연결하며 잘못된 변경/중복/영역 이탈 시 중단. 원본 운영 miner SQLite와 다른 프로젝트 자료에 접근하지 않음.
8. **EVOLVE / 재사용:** 후속 호출은 앞선 경험 로그의 결과를 검증하고 **아직 검사하지 않은 다음 부하**를 선택. 성공적 합성 결과라면 그다음 시험을 제안, 불일치·실패는 HOLD. 개선 알고리즘을 운영 도서관에 자동 적용하거나 서명·패키징·승격하지 않음.

이를 통하여 **실제로 다음 실험을 바꾸는 기억 기반 의사결정 로직**이 처음 생긴다. 단, 현재는 한 가지 합성 도서관 검색 알고리즘에만 적용되는 유한한 첫 P8 실험이며 범용 자동학습 시스템은 미완성.

## 명령

UCIE에 새 모듈 반영 후 PowerShell:

```powershell
$env:PYTHONPATH = 'D:\UCIE\src'
$py = 'D:\UCIE\.venv\Scripts\python.exe'

# 실제 다음 합성 실험을 딱 1회 수행, 경험 원장 쓰기는 하지 않음
& $py -B -m ucie_miner.experience_evolution --ucie-root 'D:\UCIE'

# 앞선 결과를 다음 실행에 재사용하고 싶을 때만 명시적으로 기록
& $py -B -m ucie_miner.experience_evolution --ucie-root 'D:\UCIE' --record

# 다음 날 같은 기록 명령을 다시 실행하면 중복 실험 대신 다음 새 부하 선택
& $py -B -m ucie_miner.experience_evolution --ucie-root 'D:\UCIE' --record
```

현재 이전 W08의 사용자 실측(1536×48)은 출처 라벨 `OWNER_OBSERVED_RECEIPT_NOT_INDEPENDENTLY_AUTHENTICATED`로 **코드 내부 기준 참고값에만 포함**. 작성 시 이미 영구 원장에 등록된 척하지 않으며, 이번부터 P8가 직접 실행한 실험만 로컬 원장에 기록한다. 기본 수행은 DB/네트워크/모델/스케줄러/운영 코드 변경 0.

## 종료 조건 및 의도적으로 미완인 것

- 합성 실험에서 반복되는 같은 부하로 결과 숫자를 채우지 않고 네 가지 부하만 한 번씩 확인하면 `NO_UNTESTED_SYNTHETIC_SCENARIOS`.
- 부정 경험은 `NEGATIVE_EXPERIENCE_HOLD_FOR_REVIEW`; 자동 적용 금지.
- 지금 P8의 진화는 **조회 알고리즘 실험 선택과 회귀 시험**까지. 전체 가상도서관 지식 검색·공식/독립 공개 자료 기여도 반영·범용 스킬/엔진 개선안 생성·실서비스 투입 등은 V1 후속 기능.
- 통합 P9 또는 운영 패키지 승인/릴리스와 결부하지 않음.
- 시간당 기존 수집 작업은 건드리지 않음. `--record` 명시없이 새 지속 저장·예약작업 등록·개인정보 학습 없음.

## 다음 개발 실무

1. 실제 사용자가 P8의 다음 합성 실험과 첫 경험 기록을 선택하면, 두 번째 실행에서 중복이 사라지고 새로운 부하로 교체되는지 확인.
2. 합성 부하 4종 완료 후, 같은 작업을 반복하지 않고 더 현실적인 **UCIE 내부 Library 질의 분포**를 보안 경계 안에서 시험할 새로운 평가 질문 정의.
3. 소스·버전·테스트 증거를 함께 가진 W05/W07 규칙/스킬 후보에도 동일한 **증거→실기→경험→개정안** 계약을 확장하되, 원본 공개 PR 제목만으로 효과 입증/자동 재사용 불가.
4. 승인된 W09 범용 패키지와 연결하려면 인수 기준/실용 효과/사용권을 별도로 확인. 사용자/프로젝트 자료를 UCIE로 다시 수집하지 않는다.
