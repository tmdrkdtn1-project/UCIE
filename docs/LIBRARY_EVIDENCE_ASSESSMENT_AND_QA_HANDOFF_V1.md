# UCIE Library — multidimensional evidence assessment and independent QA handoff V1

## Status and boundary

**Implemented in PR #77:** a deterministic **offline / read-only** inspection layer that
reuses existing PUBLIC_ONLY batch validation, five-domain Library catalog,
revision snapshot, and knowledge graph. It neither replaces nor resets those
earlier components. This document is the implementation contract, **not** an
assertion that the underlying upstream code fixes are independently verified.

**No new repository, tunnel, MCP tool, scheduler, database, training run, installed
skill, signed Rulepack, production release, or cross-project dependency.**
The fixed public source scope remains the five approved repositories:
`python/cpython`, `PowerShell/PowerShell`, `git/git`,
`modelcontextprotocol/python-sdk`, `actions/runner-images`.

## What was added

- `src/ucie_miner/public_library_assessment.py`:
  `preview_library_evidence_assessment(current, previous=None)`.
- `python -m ucie_miner preview-library-assessment-stdin` accepts an exact
  `{"current": <existing approved public batch>, "previous": <batch or null>}`
  input envelope via stdin, rejects duplicate JSON object keys and oversized
  payloads, and emits a JSON review preview. This command performs no network
  reads or disk writes.
- `tests/test_ucie_public_library_assessment.py` covers deterministic output,
  all unverified quality gates, changed-only review tasks, unchanged suppression,
  changed pinned commit / evidence fingerprint, nonselection-is-not-deletion,
  foreign URL / forged approval rejection, and valid/invalid CLI.

### P0. Multidimensional, evidence-based classification

Each reference receives a **machine-readable assessment**, bound to the
existing validated Library graph and exact public revision identity:

1. Approved source identity **format only**, technology skill domain, kind of
   public reference, and bounded metadata-based error-pattern tags.
2. Pinned upstream merge SHA / commit SHA and public evidence fingerprint;
   neither is proof of source authenticity or fix correctness.
3. Revision comparison: new in selected batch / evidence changed / pinned
   merge identity changed / unchanged within the selected scope.
4. Explicit gaps for independent upstream release-version inclusion,
   source license, security, isolated regression, independent QA, and owner
   authorization.
5. Named first-party, nonexecuting regression plan and safe review guidance.

**Confidence** is a nonnumeric `UNVERIFIED_METADATA_ONLY_NO_NUMERIC_SCORE`
classification. No percentage, invented PASS, source-version applicability,
or release coverage is inferred from PR metadata or a SHA digest.

### P1. Review handoff (initial closed-loop segment)

- Requeue only **NEW**, **EVIDENCE_FINGERPRINT_CHANGED**,
  **MERGE_IDENTITY_CHANGED** public references for independent verification.
- Unchanged references remain review-pending without a duplicate notification.
- References absent from the later **bounded selection** are recorded
  `NOT_IN_THIS_BOUNDED_SELECTION_NOT_DELETED`; this does not mean deletion or
  revocation in the underlying library.
- Each review work item is anchored to public URL, pinned revision and evidence
  fingerprint, with six independent review gates and first-party isolated
  regression guidance.
- All cards and work items remain `NO_GO`, `auto_approved=false`.
  **No actual behavior test, human QA, signature generation, Rulepack promotion
  or persistent feedback write occurs.**

This is the **classification → change detection → review work queue** portion
of the future quality loop. It does **not** complete the end-to-end closed loop:
real independent regression evidence, review-result ingestion and audited
promotion decisions still require separately gated engineering and actual
runtime QA. Existing signed-review and revocation ledgers remain distinct;
the new preview does not bypass their trust checks.

## Offline invocation

Pass an already validated UCIE-authored public batch receipt and an optional
previous receipt as a JSON object via standard input:

```powershell
$env:PYTHONPATH = 'D:\UCIE_PREVIEW\UCIE\src'
Get-Content .\synthetic_approved_batch_pair.json -Raw |
    & 'D:\UCIE\.venv\Scripts\python.exe' -B -m ucie_miner preview-library-assessment-stdin
```

The JSON file shown is an example input prepared separately, **not**
automatically generated by this feature. Do not feed private-project content.

## Acceptance and outstanding work

- Source-only CI: Python 3.13 + 3.15 on Windows and Ubuntu; no live source
  collection or production installation in tests.
- Inputs that claim preapproval, inject unsupported sources/instructions,
  alter first-party safe-call guidance, or exceed the graph's bounded scope
  must fail closed.
- Passing synthetic unit tests does not prove that the reviewed upstream fixes
  work; review card quality is limited to metadata and approved-source identity.
- A later independently authorized phase may connect verified provenance,
  exact upstream release inclusion, isolated regression receipts, immutable
  QA reviews, revocation checks, and human release approval to a separate
  candidate/Rulepack gate. **Automatic rule promotion stays OFF.**

**Owner / implementation boundary:** UCIE only. Do not reuse private
project-specific assets, repositories, chat context or credentials as learning
inputs.
