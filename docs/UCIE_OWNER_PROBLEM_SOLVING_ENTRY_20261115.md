# UCIE 개인용 문제 해결 시작 — 2026-11-15

## 소유자 발언과 방향
- 사용자는 UCIE가 기능 학습에 그치지 않고, 고객 자신의 문제를 제시했을 때 이를 분석하고 해결 방향을 내주는 서비스여야 한다고 요구했다.
- 기존 확정 문서 `docs/UCIE_SKILLBOOK_PRODUCT_MISSION_V1_20261102.md`는 4대 동등 핵심 축(오류 예방, 개발엔진·스킬·학습논리, 가상도서관, UCIE 자체 개선)과 승인된 공개 근거 기반 SkillBook을 규정한다. **임의 사용자 질문을 AI로 분석하는 고객 서비스가 완료되거나 그 세부 아키텍처가 이미 승인됐다는 근거는 없다.**
- 이번 제품 UX 방향에서 **‘내 문제 해결하기’는 4대 기술 축의 고객 진입 경험**으로 추가하되, 기존 기술 엔진과 권리·검증·배포 게이트를 변경하지 않는다.

## 이번 실제 구현 범위
기존 소유자 Windows `D:\UCIE`의 Local V04 홈에서 내 문제 해결하기가 가장 먼저 보인다. `/local/solve`에서 아래 4개 **고정 상황만** 선택할 수 있다.

1. Python ModuleNotFoundError: 실행 Python과 설치된 패키지 환경 확인
2. PowerShell 명령을 찾지 못함: 우선순위·버전 확인
3. Git 저장소가 아니라는 오류: 작업 위치·읽기 전용 상태 확인
4. MCP prompts/get 인수 오류: API 요청 계약과 오류 분류 확인

선택 후 현재 `local_error_actionable_workflow_v01.get_case`를 재사용하여 가능한 원인·검사 명령 2개·안전한 다음 단계·고정 공식 URL·기존 공개 도서관 링크를 표시한다. 사용자 PC에 있는 실제 코드, 환경, 파일, 로그를 탐색하거나 명령을 자동 실행하지 않는다. 선별된 증상 기반 점검 설명은 **그 고객 환경에서 원인을 검증한 AI 분석이 아니다**. 이해를 돕는 증상 안내이자 1차 답변 범위이다.

기존 GET-only/localhost 보호를 유지한다. `case`는 네 개의 고정 ID 외에는 차단하고 중복/빈 입력/불명 필드 차단; POST 405 유지. 자유문장 질문, 코드 붙여넣기, 파일·로그 업로드, 외부 네트워크, 모델 API 호출, 고객 개인정보·비밀정보 수집, 운영 SQLite 변경, 규칙 자동 승격, 결제·고객 배포·상용 서명은 모두 **없다**.

## 진정한 AI 문제 분석 서비스의 후속 필수 단계
실제 자유형 질문을 접수하기 전 별도 승인 및 설계가 필요하다. 우선 고객이 자신의 이슈를 기술할 수 있는 입력의 **최소 허용 범위, 민감정보 자동 차단·최소화, 명시적인 외부 전송 동의와 데이터 보존 정책**을 확정해야 한다. 이후 공식 공개 출처에 묶인 검색/인용, 모델의 추정과 검증 근거 분리, 명령·패치 자동 실행 금지, 사람이 확인하는 재현·회귀 계획, 충분한 false-positive/안전성·유용성 시험을 거쳐야 한다. 승인 없이 private code, private repository, user files, connected apps, 사용자 대화나 다른 프로젝트를 UCIE 학습 자원으로 수집·공유하지 않는다.

최종 사용자 경험 목표: **‘문제를 제시 → 가능한 원인과 추가 확인 질문 → 공식 근거와 안전한 해결 절차 → 확인 방법 → 사용자가 선택해 적용’**. 이번 단계는 고정 네 사례로 앞부분을 작동시키는 1차 제품 기능이며, 자유 질문을 생성형 모델이 처리하는 단계는 `NOT_IMPLEMENTED`이다.

정기결제·외부 고객 배포는 소유자 지시에 따라 계속 보류한다. 개인용 로컬 도구 구현이 고객에게 자동 배포 권한을 주지 않는다.
