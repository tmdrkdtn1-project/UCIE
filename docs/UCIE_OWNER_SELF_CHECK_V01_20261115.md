# UCIE 소유자 로컬 — 문제 해결 후속 점검 1문항 (2026-11-15)

## 목적

사용자 피드백: 코딩 문제를 입력한 뒤 기술 용어와 일반적인 가이드만 보이는 것보다, **내가 무엇을 확인하고 다음에 어떤 행동을 해야 하는지**가 분명해야 한다. GPU 업그레이드 전에는 Qwen을 비롯한 AI 모델 설치·학습·API 연동을 하지 않는다는 소유자의 최신 결정이 우선한다.

## 이번 변경 (비-AI)

기존 개인용 Local V04의 네 가지 공식 근거 기반 문제 안내에 사람이 직접 선택하는 **후속 확인 질문 1개**를 추가한다. 선택지는 '네, 확인했어요 / 아니요, 다릅니다 / 아직 모르겠어요'. 각 선택에 따라 미리 UCIE가 검토한 **가능한 설명과 안전한 다음 행동**을 출력한다. 질문 입력 후 네 가지 유형으로 정확히 연결된 화면에도 동일하게 나타난다.

- Python: 실행 Python 환경에서 대상 패키지가 확인되는가?
- PowerShell: 실제 문제가 난 명령이 Get-Command에 나타나는가?
- Git: 문제를 겪은 폴더에서 rev-parse의 최상위 경로 확인이 성공하는가?
- MCP: 요청 이름·인수가 prompts/list 계약과 일치하는가?

이 답변은 사용자가 직접 선택한 정보일 뿐이며, UCIE가 환경을 읽어 확인했거나 실제 버그를 수정했다는 뜻이 아니다. 미확인 질문에는 추정을 강요하지 않는다. 직접 인지하지 못한 상태에서는 기존 안전한 읽기 전용 점검으로 안내한다.

## 기술적 제한

기존 /local/solve GET에 case=4개 고정 ID, check=yes/no/unsure만 추가한다. 질문 문장·프로젝트 경로·코드·로그·개인정보·비밀정보·외부 링크를 받지 않는다. 값은 요청 URL의 비민감 선택 코드에 한정하며 선택/응답을 DB나 로그에 별도로 기록하지 않는다. 임의 모델 호출/다운로드, 공개 데이터 수집, 개인 파일 접근, 호스트 명령 실행, 유료 결제, 상용 배포, 규칙 승격, 운영 DB 변경, 스케줄러 수정 모두 없다. 허가된 공식 기술 근거 링크와 기존 감사·라이선스·승인 상태는 유지한다.

## 시험과 인수 경계

새 테스트는 4×3=12 경로의 실제 localhost GET, 응답 문구/안전한 결과, 허용되지 않는 파라미터 400, 기존 POST 405, Host/보안 헤더, 기존 source trust gate, 기존 텍스트 입력→안내 연결을 확인한다. Windows 소유자 로컬 시험, GitHub Windows/Ubuntu Python 3.13/3.15 전체 CI, clean Windows installed app 결과를 각각 확인한다.

테스트가 통과하더라도 실제 사람의 사용성 검증/고객 서비스 공개 승인, 외부 코드 수정 검증, 자유문장 AI 추론 능력까지 완료됐다는 뜻은 아니다. Qwen/모델 연결은 GPU 업그레이드 후 별도 승인될 때까지 마지막 단계로 보류하며, 자동 모델 훈련·설치·전송도 하지 않는다.
