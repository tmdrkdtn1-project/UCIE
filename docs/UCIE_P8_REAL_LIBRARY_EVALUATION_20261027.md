# UCIE P8 — 축적된 경험의 도서관 조회 + 실제 UCIE 공개 원장 검색 실험 (2026-10-27)

## 1. 사용자 실호스트에서 첫 경험 기록 확인

소유자가 직접 제공한 첫 P8 실기 기록:

- 선행 실행 `--ucie-root D:\UCIE` (미기록): `ROWS_256_QUERIES_16`, 4096회 선형 비교 vs 272회 인덱스 빌드+조회. 정답 일치. `new_event_written=false`, `database_writes=0`.
- 이어서 소유자 `--record` 실행: 같은 `ROWS_256_QUERIES_16` 합성 부하를 실제 재실행해 첫 **UCIE 전용 경험** 영수증 `event_sha256=6e6c54d7f0ebe0763528b02ae093bdac2fb24c81aec9921d37d9b11aa370a466`, `new_event_written=true`, `ucie_isolated_ledger_writes=1` 확인.
- 측정 중앙값: 기준선 353,600ns / 개선 47,000ns, 정답 일치. 해당 단일 합성 부하·호스트에 한정하고 원본 운영 도서관 성능·개별 스킬의 실제 성능이 확인됐다고 표시하지 않음.
- 위 첫 원장은 `D:\UCIE\runtime\ucie_p8_experience_v1.jsonl`이며 다음 **미실행** `ROWS_4096_QUERIES_16`이 원래 P8 루프가 선택해야 하는 항목. 이번 개발은 그 원장이나 기존 테스트를 덮어쓰지 않는다.

## 2. 이번 제품 기능의 두 축

코드: `src/ucie_miner/experience_application.py`

### A. P8 경험 도서관 서가

기존 `experience_evolution._load_events()`를 재사용하여 **기존 SHA256 연쇄를 통째로 검증**하고 UCIE 자체 경험만 읽는다. 기록된 실험을 `UCIE_EXPERIENCE` 항목으로 조회하고 다음 정보를 제공한다:

- 경험 이벤트 SHA, 이전 이벤트 SHA, 정확 실험 ID·합성 데이터 해시·부하 조건.
- 정확성, 기존 대비 작업량 감소율, 각 실험 안에서의 시간 중앙값과 진단적 비율(서로 다른 부하 간 시간 비교를 같은 성능으로 단정하지 않음).
- 중복 없는 **다음 미실행 부하**와 실패 시 HOLD 상태.
- 원장에 없는 사용자 제공 과거 W08 영수증은 `OWNER_OBSERVED_REFERENCE`로만 별도 표기; 첫 P8 기록과 혼동하지 않는다.
- 읽기·검색만 하고 새 경험/승인/자동학습/파일 변경은 하지 않는다.

### B. 실제 UCIE 공개 근거를 사용한 W08 후속 실험

첫 W08은 합성 1,536건에서 정확 결과 48/48·작업량 감소가 관측됐다. 하지만 그것만으로 실제 가상도서관에서 인덱스가 효율적이라고 할 수 없다. 이제 다음 질문을 실제 UCIE **공개 근거 메타데이터**로 시험한다.

1. 기존 `prepare_verification_handoff`와 `_checked_handoff`의 Stage10→12 검증 연결을 **읽기 전용 그대로 재사용**. UCIE 전용 저장소/원장만, 승인된 5개 공개 저장소의 기존 PR 메타데이터만.
2. W02 `build_library_entry`로 매 행의 source, SHA, URL, 목적코드 및 기술분야를 정규화. 일반 근거를 `PUBLIC_TECHNICAL_EVIDENCE`로 두고, 승인된 실스킬로 오인하지 않는다.
3. 동일한 실제 공개 근거의 정확 4중 검색키 `source_id/domain/kind/purpose_code`에 대해 기존 **선형 전체 탐색**과 새로운 **인메모리 복합키 인덱스**를 비교. 정답/미존재 조회를 모두 검사하고 **인덱스 생성 비용까지** 작업량/실행 시간에 포함.
4. 표본 공개 원장 행의 SHA256·실행 횟수·정답 불일치 수·기준선 비교량/인덱스 비용/측정 시간 중앙값을 반환. 유용성은 실제 메타데이터의 **정확 일치 필터**에서만 평가한다.
5. **W04의 전체 부분 문자열 검색과 동일 기능이 아니다.** 기존 운영 검색 인덱스를 교체하지 않고 네트워크 GET/DB 쓰기/경험 원장 추가/다른 프로젝트 접속/공개 코드 실행/규칙 승격을 하지 않는다. 338개 원장 기록이 모두 검색기에서 읽히면 실제 데이터에서 관측된 기술적 통계이며 스킬 승인이나 배포를 의미하지 않는다.

## 3. 소유자 PC 실행 명령

기존 새 코드가 `D:\UCIE\src\ucie_miner`에 반영된 뒤, 기존 수정 파일을 강제 동기화하지 말고:

```powershell
$env:PYTHONPATH='D:\UCIE\src'
$py='D:\UCIE\.venv\Scripts\python.exe'

# 이미 기록한 첫 경험을 조회하고 다음 4096x16 계획을 확인 (쓰기/재실험 없음)
& $py -B -m ucie_miner.experience_application --ucie-root 'D:\UCIE'

# 실제 UCIE Stage12 승인 범위 공개 메타데이터에서만 선형 vs 인덱스 실기 비교
& $py -B -m ucie_miner.experience_application --ucie-root 'D:\UCIE' --mode real-catalog --queries 32 --repeats 3

# 원래 P8 폐회로: 이전 256x16 기록을 확인하고 4096x16 2번째 실험을 실행·기록
& $py -B -m ucie_miner.experience_evolution --ucie-root 'D:\UCIE' --record
```

마지막 명령은 사용자가 이미 기록을 선택한 경험 원장에 **새 실험 이벤트를 1개 추가**하므로 첫 두 명령과 구분한다. 3회 연속 실험을 한 번에 예약하거나 기존 시스템 수집 스케줄러를 등록하지 않는다.

## 4. 개발 상태와 다음 작업

- **완료 목표(이번 배치):** 실제 저장된 경험이 재실험 없이 조회되고 다음 부하를 추천하는지; 실제 공개 기술 근거(읽기 전용)를 입력으로 두 알고리즘을 실행하고 정답과 비용을 비교할 수 있는지.
- **미완:** W05에서 발굴한 실제 스킬/엔진의 구현 검증·개선, 일반화된 경험 정책의 모든 산업 분야 적용, 실시간 가상도서관/독립 패키지 인덱스 도입 및 P9 완성.
- **다음 코드 묶음:** 실제 공개 메타데이터에 대한 실험 결과가 정확하고 실용적일 때, W04 검색기 옵션에 한정된 인메모리 exact lookup을 제공하는 기능을 구현(기존 전체 검색 경로 유지). 이후 P8 실험 계보와 기술·스킬별 검토 계획을 연결하고, 실사용 회귀 결과가 확인된 때만 수동 승인된 범용 패키지로 승격.

검증 기준은 `tests/test_ucie_p8_experience_application.py`: 첫 경험 해시/다음 실험/원장 불변, 임의 변조 차단, 공개 후보 검증 어댑터 재사용, 승인 범위 밖 소스/위조 승인 거부, 실제 UCIE Stage10→12 합성 원장 바이너리 불변, 네트워크/DB 무쓰기, 불일치/빈 입력 처리.
