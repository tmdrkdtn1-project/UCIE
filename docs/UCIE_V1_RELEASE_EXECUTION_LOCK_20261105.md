## 실행 순서와 작업 방식

1. **묶음 01부터 실제 기능** 개발. 기존 001/002를 재사용하여 사람/기계 자산·안전한 격리 독립 소비 초안·버전/원본 추적을 먼저 완성한다. 독립 심사·권리 승인이 없으면 `DRAFT_NOT_APPROVED`로 표시.
2. 이어서 기존 W04/P9 검색과 연결해 **묶음 02** 완성. 새 도서관 엔진 중복 생성 금지.
3. 기존 W09/P9 패키징 기반으로 **묶음 03**. 비승인 공개 코드·원본을 패키지에 섞지 않으며 실제 외부 반출은 권리/보안/서명/소유자 게이트 통과 전 차단.
4. **묶음 04** 독립 검증/실제 호환성·효과. 누락 범위를 문서로 숨기지 않음.
5. **묶음 05** 기존 P8/P11 회귀·개정 연결. 실패 사례도 기록, 자동 승격·모델 학습 없음.
6. **묶음 06** 운영형 전체 통합 시험 및 검토 증거 확보. 출시 승인 결정은 소유자 전용.

안전상 서로 독립된 일부 구현·검증은 병렬 가능하지만 최종 인수 번호는 건너뛰지 않는다. 완료 기록은 GitHub 정확 커밋·관련 PR·실호스트 영수증·Slack #ucie-project에 기록하고 다음 미완료 묶음으로 이어간다.
